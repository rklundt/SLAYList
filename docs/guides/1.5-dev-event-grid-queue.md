## Critical principles (read before clicking anything)

Three invariants. If a UI option contradicts one of these, STOP and report back.

1. **D6 — Storage Queue, not Service Bus.** Sprint 1.5 creates plain Storage Queues, no Service Bus. The "switch to Service Bus" trigger documented in D6 is "outgrown" — needing real DLQ without hand-rolled logic, or needing ordering/topics/sessions. Not us. (If a tutorial somewhere recommends Service Bus for the same scenario, ignore — D6 is the project's call.)

2. **D6 — Hand-rolled DLQ pattern.** Storage Queue has no native dead-letter primitive. The "retry + dead-letter → `failed`" behavior promised in Sprint 7.2 is **application logic in the transcoder**: track each message's dequeue count, move to `transcode-jobs-poison` when it exceeds a maximum. **Don't go looking for a portal toggle that enables DLQ on the Storage Queue** — there isn't one. The poison queue we create at Step 4 below is just a normal Storage Queue that the transcoder app code will move messages into.

3. **D25 split-auth posture extends to Event Grid.** The Event Grid system topic's system-assigned MI is the auth credential for delivery to the queue (Sprint 7.1 grants the RBAC). NO SAS token. NO storage account key. Same discipline as the Container App at Sprint 1.4. Step 5 below enables MI; Sprint 7.1 paired with subscription creation grants the RBAC.

## Troubleshooting

### "Event Grid System Topics blade not found in portal search"

Some portal versions hide it under **Event Grid** (the general blade) → click the "System Topics" tab. Or use the URL path directly: `https://portal.azure.com/#blade/HubsExtension/BrowseResource/resourceType/Microsoft.EventGrid%2FsystemTopics`.

### "The Identity tab isn't shown during Event Grid topic creation"

Some portal versions only let you enable system-assigned MI *after* creation. Create the topic first, then go to the topic → **Identity** → System assigned → On → Save. Same end state.

### "Storage account queues blade shows queues I didn't create (`$logs`, `$messages`, etc.)"

Azure auto-creates some system-internal queues for logging/management. They're harmless and don't conflict with our `transcode-jobs` / `transcode-jobs-poison` names.

### "Diagnostic settings dropdown doesn't show the LAW"

The LAW from Sprint 1.1 (`log-music-slaylist-dev-use2`) must be in the same subscription. Verify subscription = `Pay-As-You-Go` on both the storage account / Event Grid topic AND the workspace.

### "I see Successful Deliveries / Successful Publishes categories in Event Grid diagnostic logs — should I include them?"

**No** — at family scale, every successful delivery generates a log row; for the transcode path that's one row per upload. Useful in a high-volume system; noise for us. Only the failure categories are worth ingesting.
