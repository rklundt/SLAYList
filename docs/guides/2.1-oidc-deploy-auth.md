# Deploy identity (OIDC, environment-based) — operator guide

Sets up the credential GitHub Actions uses to deploy to Azure — via **OIDC federation, no stored secret** (D30/D37) — provisioned by a committed, idempotent **bootstrap script** rather than Bicep or portal clicks (D41).

> **History:** Sprint 2.1 first set this up branch-keyed with repo-scoped secrets. Sprint 2.2 reworked it to **environment-based** (federation keyed to a GitHub *environment*, secrets *environment-scoped*) — see D30's implementation notes. **This guide describes the current (environment-based) model.** A fresh bootstrap creates environment-scoped secrets directly; there is no repo-secrets-then-migrate.

## The one-liner

From the repo root (PowerShell):

```
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap-deploy-identity.ps1
```

That's the whole setup for dev. The script is self-documenting — `Get-Help .\scripts\bootstrap-deploy-identity.ps1 -Full`. Flags:

- `-DryRun` — print every create/set without doing it. **Run this first.**
- `-RunUpToStep N` — run only steps 1..N then stop (cautious, incremental).
- `-Env prod -ResourceGroup rg-music-slaylist-prod-use2` — the prod bootstrap (Epic 9): a **separate** `slaylist-github-deploy-prod` app (D7), and the `prod` GitHub environment gated to **`main` only**.

If PowerShell's execution policy blocks it, prefix with `powershell -ExecutionPolicy Bypass -File …` (above) or set it once: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. The operator needs `az login` (the env's subscription) and `gh auth login` with **repo admin** (creating environments needs admin).

## What each step is (and the manual Azure/GitHub-portal equivalent)

Each is check-then-create (idempotent). Portal equivalents if you'd rather see it by hand:

**1. App registration** — the *identity* GitHub Actions acts as.
- *Portal:* Microsoft Entra ID → App registrations → New registration → `slaylist-github-deploy-dev` → Register.

**2. Service principal** — the identity's usable instance (an **Enterprise Application**). The portal auto-creates it when you register via UI; the CLI doesn't (so it's a separate `az ad sp create`).

**3. Federated credential (environment-based)** — the OIDC trust: "Actions deploying to the `dev` *environment* may BE this identity." No secret.
- *Portal:* the app → Certificates & secrets → **Federated credentials** → Add → scenario **"GitHub Actions deploying Azure resources"** → Organization `rklundt`, Repository `SLAYList`, **Entity type `Environment`**, Environment name `dev` (→ subject `repo:rklundt/SLAYList:environment:dev`) → Name `github-rklundt-SLAYList-env-dev` → Add. (The script also removes any leftover *branch*-based credential.)

**4. Contributor RBAC on the env RG ONLY** (never the subscription — D30/D7).
- *Portal:* `rg-music-slaylist-dev-use2` → Access control (IAM) → Add role assignment → Contributor → select `slaylist-github-deploy-dev`.

**5. GitHub environment** — the deploy-trust target + the branch gate.
- *Portal:* repo → Settings → **Environments** → New environment `dev`. **Deployment branches:** "No restriction" (any branch can deploy to dev). For `prod`: restrict to `main` (+ optionally required reviewers).
- This is what makes GitHub mint an OIDC token with the `environment:dev` subject when a job runs `environment: dev`.

**6–7. Environment SECRETS** (scoped to the `dev` environment, not the repo) — `gh secret set --env dev`:
- `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` (stored as secrets, not variables — public-repo log-masking; D30 note).
- `AZURE_STORAGE_CONNECTION_STRING` (D25), `APPINSIGHTS_CONNECTION_STRING` (D24) — genuinely sensitive, fetched live from Azure.
- *Portal/UI:* repo → Settings → Secrets and variables → Actions → **Environment secrets** → `dev` → add each.
- **NOT set (D37):** the SWA deployment token — break-glass only, gitignored notes. The script also deletes any superseded *repo*-scoped copies.

## Verify + attest

The script ends by printing `gh secret list --env dev` (expect the **5**), `gh secret list --repo` (expect **empty** — superseded by env-scoped), and `gh variable list` (empty). Record in gitignored `infra/dev-resources.md`: the app/client/tenant/subscription IDs, the **environment** federated subject, the RBAC scope, the GitHub environment + branch policy, and the secret list.

## After this

The Sprint 2.2 workflow's deploy job declares `environment: dev`, which is what makes the environment-based OIDC token + env-scoped secrets available. Because the `dev` environment allows **any branch**, you can test the deploy from a feature branch — no temporary credentials needed. Prod (Epic 9) re-runs the script with `-Env prod` and is gated to `main`.
