# Sprint 1.7 — Reconcile the live dev RG to the Bicep (Phase B walkthrough)

This guide applies the `infra/bicep/` templates to the **live** `rg-music-slaylist-dev-use2` so dev's resources are tagged `managed-by=bicep` (+ a `region` tag) and future dev drift is caught by `what-if`. After this, dev is managed exactly like prod will be (Sprint 9.1).

**This mutates the real dev environment.** It is safe on the data plane (the pre-flight `what-if` confirms zero changes to retention/versioning/SKU/data), but it is a deliberate, consequential step — hence its own sprint and its own walkthrough.

**Time:** ~15 min. **Cost:** none.

**Prereqs:**
- `az` logged into the **personal** subscription (the `Pay-As-You-Go` one that hosts the dev RG — its id is in gitignored `infra/dev-resources.md`). Confirm with `az account show`.
- On `develop` (or this sprint branch) with the current `infra/bicep/` — the templates were made dev-faithful at Sprint 1.6.

## Why the delete-first step exists (read once)

The Bicep names role assignments **deterministically** (`guid(scope, principal, roleId)`). Dev's two existing assignments were created by hand in Sprint 1.4 with **random** GUID names. Azure rejects creating a *second* assignment for the same identity + role + scope — even under a new name — with `409 RoleAssignmentExists`. So we delete dev's two existing assignments first; the deploy then recreates them with the deterministic names. There's a brief window where the placeholder Container App's identity has no storage RBAC — harmless today (scale-to-zero placeholder, no real workload, no real data per D28).

Full reasoning: `docs/DECISIONS.md` **D39** ("Role-assignment GUIDs differ…").

## Steps

### 0. Confirm session + clean pre-flight

```
az account show --query "{user:user.name, sub:name}" -o json
```

Then re-run the read-only pre-flight (changes nothing) and eyeball it:

```
az deployment group what-if \
  --resource-group rg-music-slaylist-dev-use2 \
  --template-file infra/bicep/main.bicep \
  --parameters env=dev region=use2 workload=music app=slaylist \
      notificationEmail=<your-email> budgetStartDate=2026-05-01
```

**Expected** (per D39 "known what-if interpretation notes"): only `managed-by`/`region` tag changes, computed-field noise (`stableInboundIP`, `runningStatus`, encryption-scope defaults, etc.), the budget 33%-rung action-group decouple, and **2 role-assignment Creates**. **Any *new* delta on a data property (retention days, versioning, SKU, network access, a resource being deleted) → STOP and re-assess.** Do not proceed on a surprising diff.

### 1. Delete dev's two existing role assignments

These are scoped to the storage account, on the Container App's managed identity. Fetch the principal id live (no hardcoded GUIDs):

```
SUB=$(az account show --query id -o tsv)
SCOPE="/subscriptions/$SUB/resourceGroups/rg-music-slaylist-dev-use2/providers/Microsoft.Storage/storageAccounts/stmusicslaylistdevuse2"
CA_MI=$(az containerapp show -n ca-music-slaylist-dev-use2 -g rg-music-slaylist-dev-use2 --query identity.principalId -o tsv)

# list before (expect: Storage Blob Data Contributor + Storage Table Data Contributor)
az role assignment list --assignee "$CA_MI" --scope "$SCOPE" --query "[].roleDefinitionName" -o tsv

# delete both
az role assignment delete --assignee "$CA_MI" --role "Storage Blob Data Contributor"  --scope "$SCOPE"
az role assignment delete --assignee "$CA_MI" --role "Storage Table Data Contributor" --scope "$SCOPE"

# confirm empty
az role assignment list --assignee "$CA_MI" --scope "$SCOPE" --query "[].roleDefinitionName" -o tsv
```

(Windows `cmd`/PowerShell: set the three variables with the shell's own syntax, or paste the resolved values. In Git Bash the above works as-is.)

### 2. Apply the Bicep to live dev

```
az deployment group create \
  --resource-group rg-music-slaylist-dev-use2 \
  --name sprint-1.7-reconcile \
  --template-file infra/bicep/main.bicep \
  --parameters env=dev region=use2 workload=music app=slaylist \
      notificationEmail=<your-email> budgetStartDate=2026-05-01
```

- `budgetStartDate=2026-05-01` is **required** — the dev budget already exists with that start month, and `startDate` is immutable; omitting it lets the default compute the current month and the deploy fails on the budget. (See D39 / the budget param doc.)
- Expected: ~2–3 min, `provisioningState: Succeeded`. Idempotent — most resources are no-ops (only tags + the two recreated role assignments + the budget-notification reshape actually change).

### 3. Verify (tags, RBAC recreated, data intact)

```
# a. tags now managed-by=bicep + region=use2
az resource show -g rg-music-slaylist-dev-use2 -n stmusicslaylistdevuse2 \
  --resource-type Microsoft.Storage/storageAccounts --query tags -o json

# b. the two role assignments are back (deterministic GUIDs now)
az role assignment list --assignee "$CA_MI" --scope "$SCOPE" \
  --query "[].{role:roleDefinitionName, name:name}" -o table

# c. DATA SAFETY: blob soft-delete still 30d + versioning still on (must be unchanged)
az storage account blob-service-properties show --account-name stmusicslaylistdevuse2 \
  --query "{softDeleteDays:deleteRetentionPolicy.days, containerSoftDeleteDays:containerDeleteRetentionPolicy.days, versioning:isVersioningEnabled}" -o json

# d. containers/table/queues all still present (no data-store disruption, D7/D28)
az storage container list --account-name stmusicslaylistdevuse2 --auth-mode login --query "[].name" -o tsv
az storage table list --account-name stmusicslaylistdevuse2 --auth-mode login --query "[].name" -o tsv

# e. budget still firing-capable
az consumption budget list --query "[?name=='budget-music-slaylist-dev'].{amount:amount, thresholds:notifications.*.threshold}" -o json
```

**Expected:** (a) tags include `managed-by=bicep` + `region=use2`; (b) two assignments present, **Blob + Table Data Contributor**; (c) `softDeleteDays=30`, `containerSoftDeleteDays=30`, `versioning=true` — **unchanged** (if any of these changed, that's a data-safety regression — investigate immediately); (d) `raw-uploads`/`finished`/`table-backups` + `Songs` table all present; (e) budget at $15 with the 33/80/100 rungs.

### 4. Attest

In gitignored `infra/dev-resources.md`, add a `## Sprint 1.7 — dev IaC reconcile attestation` section: date, that the pre-flight matched D39 notes, that both role assignments were deleted then recreated with deterministic GUIDs, and that the data-safety checks (3c/3d) were unchanged. That attestation is the Phase B acceptance evidence.

## If something goes wrong

- **Deploy fails on the budget (`startDate`/immutable):** you omitted or mismatched `budgetStartDate=2026-05-01`. Re-run with it.
- **Deploy fails on `RoleAssignmentExists` (409):** Step 1's deletes didn't fully apply (RBAC deletes can take a few seconds to propagate). Re-list to confirm empty, wait ~30s, re-deploy.
- **A data property shows as changing in the pre-flight or post-verify:** STOP. The reconcile is supposed to touch only tags + RBAC naming + the budget-notification reshape. A retention/versioning/SKU change means something is off in the templates vs. dev — do not proceed; re-open the Bicep.
- **Recreate the deleted assignments without deploying (rollback):** if you delete in Step 1 then decide to abort, just re-grant the two roles by hand:
  `az role assignment create --assignee "$CA_MI" --role "Storage Blob Data Contributor" --scope "$SCOPE"` (and the Table one). Dev is then back to its pre-1.7 state.
