## Critical safeguard (read before doing anything in the portal)

SWA's portal creation flow offers a "GitHub" deployment-source option. **Choosing it would:**
1. Auto-create a `.github/workflows/azure-static-web-apps-<random-suffix>.yml` file in your repo
2. Use the SWA deployment token (stored as a GitHub Actions secret) — *exactly the long-lived secret D37 says NOT to put in GitHub Secrets*
3. Immediately trigger a deploy of the current `develop` HEAD — which today has *no D22 auth gate* (the gate is Sprint 2.2's job)

Result: **a publicly-reachable-without-auth SWA on commit one of the resource existing**, violating D22 on its first second of existence, AND a D37-violating secret in your repo.

**You will choose "Other" for Deployment source at Step 3.** This is the single most important decision in the whole sprint. If the UI changes and "Other" is renamed, the safe choice is whichever option does NOT link to a GitHub repository.

1. Portal search → **Static Web Apps** → **+ Create**.

2. **Basics tab — fill in:**
   - **Subscription:** `Pay-As-You-Go`
   - **Resource group:** `rg-music-slaylist-dev-use2` *(verify carefully — this is the placement check)*
   - **Name:** `swa-music-slaylist-dev-use2`

   - **Source Control / Source / Deployment details:** see Step 3a below ⚠️
   - **Region for Azure Functions API and staging environments:** **East US 2** *(matches our naming convention region; some portal versions split this from a "Region" field — set both to East US 2 if asked)*

3a. **⚠️ THE CRITICAL SAFEGUARD: Deployment source.** The portal will offer a "Source" / "Deployment source" choice with options like `GitHub`, `Azure DevOps`, or `Other`. **Choose `Other`.**
   - **What you'll see if you pick `Other`:** the form collapses the GitHub-integration fields and the SWA is created as an empty deploy target.
   - **What happens if you accidentally pick `GitHub`:** the portal will ask you to authorize GitHub access, pick a repo (`rklundt/SLAYList`) and a branch (`develop`), and offer to "Create workflow file." If you proceed, Azure pushes a new workflow file to your repo AND triggers an immediate deploy of the current `develop` HEAD without the D22 auth gate. **If you find yourself at the GitHub-repo-picker screen, BACK OUT now and re-pick `Other`.**

4. **Tags tab** (Next → Tags): add the same five tags as Sprint 1.1:
   - `app=slaylist`
   - `env=dev`
   - `workload=music`
   - `managed-by=manual`
   - `cost-center=personal`

5. **Review + Create** → confirm everything (especially Plan type = Free and Source = Other) → **Create**. Wait ~60 seconds.

## Step 5 — Capture the deployment token (to gitignored local notes ONLY)

Per D37, the deployment token is captured as a break-glass fallback in your gitignored local notes — **never in GitHub Secrets, never in any committed file.**

1. On the SWA resource → left nav → **Overview** → top toolbar → **Manage deployment token** (some portal versions: **Settings → Configuration → Deployment token**). Copy the full token (a long base64-looking string).

2. Open `infra/dev-resources.md` (the gitignored file you have locally from Sprint 1.1) and paste the token into the **Static Web App** section, in the "Deployment token (break-glass fallback)" row. **Paste it back to Claude Code in chat** so Claude Code can write it into the right row of the local notes (avoids fat-fingering).

3. **SECURITY CHECK before pasting:** the SWA deployment token is a high-blast-radius secret — anyone with it can push arbitrary content to your SWA. It lives in `infra/dev-resources.md` (gitignored) and the Azure portal. It does NOT live in chat history outside this session, in any committed file, in any GitHub Actions secret, or in any backup that isn't itself encrypted at rest.

4. Capture in `dev-resources.md` Static Web App section:
   - Default hostname (`*.azurestaticapps.net` — visible on the Overview page)
   - Resource ID (from Overview → JSON View → copy the `"id"` field)
   - Deployment token (the value from Step 5.1 above)

## Troubleshooting

### "I see SLAYList content at the SWA URL, not the placeholder page"

The auto-deploy safeguard failed — either "Other" wasn't selected, or it didn't take. Steps:
1. Check `.github/workflows/` on `develop` for a new `azure-static-web-apps-*.yml`. If present, delete it via the GitHub UI (a commit will be needed; tell Claude Code first so we coordinate the commit message).
2. In the SWA portal blade → **Deployment configuration** → look for any linked GitHub workflow → disconnect it.
3. **Rotate the SWA deployment token** (Manage deployment token → Reset). The old token is potentially in CI logs of the auto-triggered run — treat it as compromised.
4. Update `infra/dev-resources.md` with the new token.

### "The 'Plan type' dropdown only shows 'Standard'"

Unusual but happens with some subscription configurations. Try a different region in the basics tab (sometimes Free is region-gated). Or use the Azure CLI alternative: `az staticwebapp create --name swa-music-slaylist-dev-use2 --resource-group rg-music-slaylist-dev-use2 --location eastus2 --sku Free` — but be careful, this CLI command does NOT auto-create a GitHub workflow (good for us).

### "Manage deployment token says I don't have permission"

The role required is Owner or Contributor on the SWA. As subscription Owner you should have this implicitly. If denied, check that you're in the right tenant.

### "I accidentally picked GitHub for Deployment source and now there's a workflow"

See "I see SLAYList content..." above. The recovery path is the same.
