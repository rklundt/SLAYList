# Wire the SWA to the custom Entra login — operator guide (Sprint 3.3)

This is the sprint where **login actually goes live** on the deployed dev app. Most of 3.3 is committed code (Phase A — the `staticwebapp.config.json` custom-provider block, the API role-check, the workflow wiring). Your part (Phase B) is the two credentials that can't live in a public repo: the **client secret** and the **redirect URI** on `slaylist-auth-dev`, plus storing the client id/secret as GitHub secrets.

> **Hygiene (D17):** the client secret is sensitive and the tenant ID is an identifier — **neither goes in a committed file.** The repo's config carries a `<TENANT_ID>` placeholder (the deploy workflow substitutes the real value from the `AZURE_TENANT_ID` secret); the client id/secret live as GitHub `dev`-environment secrets + your gitignored notes.
>
> **This sprint deploys.** The D22 gate stays in the artifact — the route rule + `401 → /.auth/login/aad` are unchanged; the config just adds the custom registration so that login now uses *our* app. The gate is never absent, only strengthened.

## Step 1 — create the redirect URI + client secret (scripted)

From the repo root (PowerShell), run the extended bootstrap script. It sets the reply URL (step 5) and creates a 24-month client secret (step 6), printing the secret **once**:

```
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap-auth-app.ps1 -RunUpToStep 6
```

- `-DryRun` first to preview (nothing is created).
- The script derives the reply URL from the dev SWA's hostname: `https://<dev-swa-host>/.auth/login/aad/callback`.
- It creates a client secret **only if none exists** (secrets can't be re-read, so it won't churn them). To deliberately rotate later: add `-RotateSecret`.
- **Copy the printed secret immediately** — it's shown once.

**Portal equivalents** (if you'd rather do it by hand):
- *Redirect URI:* Entra ID → App registrations → `slaylist-auth-dev` → **Authentication** → Add a platform → **Web** → Redirect URI = `https://<dev-swa-host>/.auth/login/aad/callback` → Configure.
- *Client secret:* same app → **Certificates & secrets** → **Client secrets** → New client secret → expiry **24 months** → Add → **copy the Value now**.

## Step 2 — store the credentials as GitHub `dev`-environment secrets

The deploy workflow reads these (same pattern as the connection strings). Set them on the **`dev` environment** (not repo-scoped):

| GitHub `dev` env secret | Value |
|---|---|
| `AAD_CLIENT_ID` | the app's **Application (client) ID** (`slaylist-auth-dev`) |
| `AAD_CLIENT_SECRET` | the secret **Value** from Step 1 |
| `AZURE_TENANT_ID` | already set (Sprint 2.1) — the workflow substitutes it into the config |

```
gh secret set AAD_CLIENT_ID     --env dev --repo rklundt/SLAYList   # paste the appId
gh secret set AAD_CLIENT_SECRET --env dev --repo rklundt/SLAYList   # paste the secret Value
```
(Or: repo → Settings → Environments → `dev` → Environment secrets → Add.)

Record the appId + where the secret is stored in gitignored `infra/dev-resources.md`. **Never** paste the secret into a committed file.

## Step 3 — deploy

The config + workflow are already on the sprint branch. Once 3.3 merges to `develop` (or via `workflow_dispatch`), the pipeline: wires `AAD_CLIENT_ID`/`AAD_CLIENT_SECRET` into SWA app settings, substitutes the real tenant ID into the `dist` config, and deploys. From that deploy on, the gate's login uses `slaylist-auth-dev`.

## Step 4 — verify (the load-bearing check)

On the deployed dev URL:
- **Sign in as an assigned account** (`Alannah` → uploader, or `slay-admin` → admin). Login should complete via **your** Entra app (not the generic Microsoft prompt).
- **`GET /api/me`** (in that signed-in session) returns `{"role":"uploader"}` or `{"role":"admin"}` — this confirms the app `roles` claim reaches the API (the Free-tier claim pass-through we're verifying; if the role comes back `null`/absent, that's the D26 escalation trigger — stop and flag).
- **A non-assigned Microsoft account cannot complete sign-in** (Entra blocks it via `appRoleAssignmentRequired`) — the any-Microsoft-account gap from Epic 2 is closed.

## Rotation (future)

The secret expires in 24 months. To rotate: re-run `bootstrap-auth-app.ps1 -RunUpToStep 6 -RotateSecret`, update the `AAD_CLIENT_SECRET` GitHub secret with the new value, redeploy. Tracked in BACKLOG.
