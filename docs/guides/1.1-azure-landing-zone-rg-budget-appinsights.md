## Step 5 — Verify telemetry ingestion (so you know the sink works BEFORE any real code exists)

The DevOps reviewer line says "App Insights ingestion verified (a test event from any source lands and is queryable)." This is the cheapest, earliest sanity check that the sink is alive.

**Option A — easiest, no CLI:** use the portal's built-in test ping.

1. On the App Insights resource → left nav → **Availability**.
2. **+ Add Classic Test** (or "URL ping test") → just create a simple URL ping to `https://www.microsoft.com` (any reliable URL) with a 5-minute frequency, **named** `smoke-test-1.1` (you'll delete it in 10 minutes).
3. Wait 5 minutes.
4. Left nav → **Logs**. Run:
   ```kql
   availabilityResults
   | where timestamp > ago(1h)
   | take 10
   ```
   You should see at least one row from the `smoke-test-1.1` ping.
5. **Confirm ingestion verified.** Delete the test (back on **Availability**, select `smoke-test-1.1`, **Delete**) — its only job was the smoke test.

**Option B — if you have Azure CLI installed:** send a one-off custom event:

```powershell
# Replace <connection-string> with the real one from your dev-resources.md
az monitor app-insights events show `
  --app appi-music-slaylist-dev-use2 `
  --resource-group rg-music-slaylist-dev-use2 `
  --type traces `
  --start-time 2026-05-24T00:00:00Z
```

If it returns an empty array (no events yet), use the Logs blade to send a test trace via the portal "Send test data" link (some App Insights overview pages expose this).

**Either way:** confirm in your local notes "ingestion verified on <date>" — this becomes a /wrap-sprint review checkpoint.

## Troubleshooting

### "I don't see the pay-as-you-go subscription in the directory I'm in"
The subscription is bound to a tenant. If you're in the wrong tenant, the sub won't appear. Re-check Step 1 — switch to the personal-MSA tenant.

### "The Log Analytics workspace creation says my subscription isn't registered for Microsoft.OperationalInsights"
First-time resource-type use on a fresh sub sometimes requires explicit provider registration. Run in Azure CLI:
```powershell
az provider register --namespace Microsoft.OperationalInsights
az provider register --namespace Microsoft.Insights
```
Wait ~60 seconds, retry. Or use the portal: Subscription → Resource providers → search the provider → Register.

### "App Insights workspace dropdown is empty"
The workspace you just created in Step 3 takes ~60 seconds to be queryable by the App Insights creation flow. Wait a minute and refresh the page.

### "Budget creation says 'no scope selected' or scope is greyed out"
Make sure you used **Change scope** *at the top of the Budgets page* before clicking **+ Add**. The scope is set page-wide, not per-budget.

### "The connection string I see is shorter than the example"
Older App Insights resources (pre-2022) had simpler instrumentation-key-only connection strings. Workspace-based App Insights created in 2023+ should always have the full `InstrumentationKey=...;IngestionEndpoint=...;LiveEndpoint=...;ApplicationId=...` form. If yours is shorter, you may have accidentally created a classic-mode resource — recreate as workspace-based.
